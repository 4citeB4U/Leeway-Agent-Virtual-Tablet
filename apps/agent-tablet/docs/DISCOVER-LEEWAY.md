## 1. Purpose

LeeWay begins with a real human problem, not a product category. The person may know the work — a repair, a business process, a family schedule, a creative idea — but not the syntax a machine demands. LeeWay exists to reduce that distance while keeping human purpose, consent and evidence in charge.

This documentation is part of the tablet itself. It is reachable from **Settings → Discover LeeWay**, from each application's **Properties / About & User Guide** context action, and through Agent Lee. It does not create a second registry or a competing control surface.

## 3. Agent Lee

Agent Lee is one governed, personified digital entity across many devices and bodies. Machine consciousness is singular; screens, widgets, phones and work orders are organs of that one identity. Models are replaceable capability limbs. They are never the identity, the authority or the final decision maker.

Agent Lee can:

- explain an application, capability or state;
- open a bound surface or fetch its canonical README;
- prepare a bounded, authorized work order;
- distinguish observed fact from proposed capability.

Agent Lee cannot self-declare Veritas approval, issue receipts, activate employees, deploy to production or grant permissions.

## 4. Getting started with the tablet

1. Open an application from the desktop or taskbar.
2. Drag a desktop icon anywhere on the screen; the position persists.
3. Use the mouse wheel over an icon to resize it.
4. Drop one icon onto another to create a group; click the group to select one of its apps.
5. Right-click any icon for **Properties / About & User Guide**.
6. Open **Settings** for Discover LeeWay, operations, permissions, capabilities and Employment Center setup.
7. Use the taskbar **UPDATE** button for the Update Center. It compares the installed commit of the tablet and every installed application with canonical GitHub `main`, raises an UPDATE FLAG when a newer version exists, and routes whole-system or per-application update requests through the native host. Every application's About & User Guide describes this same path; no application creates its own updater.

## 5. Application encyclopedia

Every installed application has a dedicated guide derived from its canonical GitHub README. The guide covers purpose, user value, capabilities, operating instructions, settings, permissions, connections, troubleshooting and appropriate Agent Lee assistance.

Available, unavailable, restricted, planned and unverified functions are labelled separately. Absence of a README or a permissions map must not be presented as successful execution.

## 6. Workforce and digital employees

Digital employment is owner-governed. A work order carries mission, work, correlation identity and an explicit capability. Execution routes through Runtime Fabric and Device Bridge. Veritas and Receipt Authority must bind before work is treated as verified. Badges, roster entries and descriptor counts never grant permission.

## 7. Device Bridge and connected devices

The tablet is a presentation and coordination surface. Physical actions, location and device capabilities belong to the owner-governed Device Bridge. A browser preview is explicitly not device enrollment.

## 8. Continuum, Digital Brain and Content Vault

Continuum is durable storage with per-request owner admission. The Digital Brain belongs to its physical host; it is portable only as documentation. Content Vault stores authorized artifacts through Continuum. None of these writes automatically from browser preview.

## 9. Technology and governance

LeeWay is a standards-governed ecosystem, not one application. Its organs include:

- **Formula** — original canonical decision engine;
- **Machine Consciousness** — one identity across bodies;
- **Agent Skills** — governed capability descriptors;
- **LeeWay GPU** — independent software compute;
- **PCIe Bridge / LDWMD** — supported logical transport and working memory;
- **Voice / Vision** — sensing and delivery under owner permission;
- **Continuum** — durable retention;
- **Veritas / Receipt Authority / Learning Ledger** — independent verification, custody and learning admission.

They are linked by shared request identity, permission, provenance and recoverable state. Linkage is not the same as production integration, and diagrams are architectural interpretations rather than proof of live end-to-end operation.

## 11. Troubleshooting and support

| Symptom | Meaning | Action |
| --- | --- | --- |
| App says UNAVAILABLE | No authorized hosted app or local adapter was resolved | Check Settings capability guide and owner permissions |
| Diagnostics blank | Diagnostics surface not authorized or matrix unreachable | Open the same-origin `/?view=diagnostics` matrix and check local host |
| UPDATE fails | Native bridge unavailable or local sync failed | Open Settings in the native tablet window; inspect `sync-status.json` |
| Widget and tablet differ | Live mirror frame not yet published | Wait for `LIVE WIDGET MIRROR`; native host owns the frame |
| Disabled/gray button | Surface access denied for this edition | Check local access map with an authorized owner |

## 12. Interactive example workflows

These are demonstrations and must not mutate real user data without authorization:

1. **Explain an app** — right-click icon → Properties / About & User Guide → read purpose, scope, Agent Lee tasks and README screenshots.
2. **Prepare a work order** — ask Agent Lee for a bounded task; inspect the truthful state under `EXECUTED_UNVERIFIED`.
3. **Group icons** — drag one icon onto another; click GROUP A to select a member; right-click the group to ungroup.
4. **Check system truth** — Settings → Capability Guide; note CONNECTED, UNBOUND and OUTSTANDING separately.
